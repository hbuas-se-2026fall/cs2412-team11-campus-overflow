# CampusOverflow 代码评审清单 v1.0

适用范围：本仓库所有 PR（后端 Java、前端 TypeScript、部署与文档）。
使用方式：评审人逐条对照，不符合的项在 PR 评论中引用编号并说明原因。
版本：v1.0（Lab 7，第 13 周）

## 1. 正确性

- [ ] C1 边界条件已覆盖：空值、最小值、最大值、超长输入
- [ ] C2 异常路径有明确处理，未吞掉异常
- [ ] C3 事务边界正确：跨聚合写操作在同一事务内，或明确最终一致
- [ ] C4 并发场景有考虑：幂等、唯一约束、乐观锁/悲观锁
- [ ] C5 状态机转换合法：非法状态转移被拒绝并有测试
- [ ] C6 时间与排序：使用统一时钟源，分页排序稳定

## 2. 可读性

- [ ] R1 命名达意：类名是名词，方法名是动词，布尔以 is/has 开头
- [ ] R2 方法长度 ≤ 40 行，圈复杂度可控
- [ ] R3 魔法值已提取为常量或枚举
- [ ] R4 注释解释"为什么"而不是"做了什么"，无过期注释
- [ ] R5 无死代码、无注释掉的代码块

## 3. 可测性

- [ ] T1 依赖通过构造器注入，便于替换
- [ ] T2 无隐藏状态：不依赖静态可变字段、系统时间、随机数
- [ ] T3 输出可断言：方法返回结果而不是只产生副作用
- [ ] T4 副作用可验证：外部调用通过接口隔离，可用 ArgumentCaptor 断言
- [ ] T5 新增分支逻辑有对应单元测试

## 4. 安全

- [ ] S1 所有外部输入经过校验（Bean Validation / 前端表单校验）
- [ ] S2 资源级授权：先校验归属关系，再执行写操作
- [ ] S3 敏感信息脱敏后输出（邮箱、手机号、密码）
- [ ] S4 写操作有 CSRF 防护，Cookie 设置 HttpOnly / SameSite
- [ ] S5 无 SQL 拼接，全部参数化
- [ ] S6 错误响应不泄露堆栈与内部路径

## 5. 性能

- [ ] P1 列表查询分页，无全表加载
- [ ] P2 无 N+1 查询，关联数据一次批量取回
- [ ] P3 查询条件命中索引
- [ ] P4 无循环内远程调用
- [ ] P5 循环内无重复计算，可提取到循环外

## 6. 风格与工程规范

- [ ] E1 `mvn -B verify` 通过（含 Checkstyle）
- [ ] E2 `pnpm lint` 与 `pnpm typecheck` 无输出
- [ ] E3 提交信息符合 `type(scope): subject` 格式
- [ ] E4 改动聚焦：一个 PR 只做一件事
- [ ] E5 无调试残留（console.log、System.out、TODO 无负责人）

## 评审记录要求

- 每位评审人至少留下 5 条实质性意见
- 每条意见须包含：引用清单编号、具体代码位置、建议改法
- 作者回应后，评审人确认或继续追问，直至关闭
